\section{Introduction}
Suppose a bit stream has been encoded by a convolutional code and sent over a noisy channel. Given the received sequence \(y\), a noisy version of the transmitted codeword, how do we recover the codeword \(c\)? Because the noise is random, no decoder can be sure to find the transmitted codeword. Instead, our task is to find the \emph{most likely} codeword.

For convolutional codes, there is a remarkably efficient algorithm, called \emph{Viterbi decoding}, that is guaranteed to find the maximum likelihood codeword. Andrew Viterbi proposed the algorithm in 1967; in 1973, David Forney showed that it is exactly a maximum likelihood decoder and gave the trellis interpretation we use today.

In this lecture we describe this algorithm. We will see that Viterbi decoding is dynamic programming applied to the trellis of the convolutional code: the problem of finding the most likely codeword becomes the problem of finding the best path through the trellis.

We proceed as follows. Section~\ref{sec:ml} formulates maximum likelihood decoding. Sections~\ref{sec:hard} and~\ref{sec:soft} derive the decoding metric for hard decisions (the BSC) and soft decisions (the AWGN channel), and Section~\ref{sec:branch} turns it into branch metrics on the trellis. Sections~\ref{sec:dp} and~\ref{sec:viterbi} develop the dynamic program and state the Viterbi algorithm, with a worked example. We then discuss how to change the code rate (Section~\ref{sec:rate}), the complexity of the algorithm (Section~\ref{sec:complexity}), and the performance of convolutional codes on the BSC (Section~\ref{sec:conv_perf}).

Throughout, we use the rate-\(1/2\), \(K=3\) example code from the previous lecture:
\[p_0[n] = x[n] + x[n-1] + x[n-2], \qquad p_1[n] = x[n] + x[n-2],\]
with generators \((7,5)\) in octal. Its state at time \(n\) is \(x[n-1]x[n-2]\), so it has \(2^{K-1} = 4\) states. For reference, its eight branches are:

\end{center}

\section{Maximum Likelihood Decoder}\label{sec:ml}
The quantity \(p(y|c)\) is the probability of receiving the sequence \(y\) given that codeword \(c\) was transmitted. A maximum likelihood (ML) decoder chooses the codeword that maximizes this probability. When all messages are equally likely, this is also the decoder with the smallest probability of choosing the wrong codeword.

We group the transmitted bits by time step. For a rate-\(1/r\) code, each input bit produces a block of \(r\) coded bits, \(c_i = c_i^1 c_i^2 \cdots c_i^r\), and we write \(y_i = y_i^1 y_i^2 \cdots y_i^r\) for the corresponding received values. If the channel is memoryless, the noise acts independently on each transmitted bit, so
\begin{equation}
p(y|c) = \prod_{i=1}^{n}p(y_i|c_i), \label{eq:pyc}
\end{equation}
where \(n\) is the number of time steps. Each factor splits further as \(p(y_i|c_i) = \prod_{j=1}^{r}p(y_i^{j}|c_i^{j})\); we keep the block form for now to avoid clutter and use the bit-level form in Section~\ref{sec:branch}.

The ML decoder therefore chooses
\begin{equation}
    c_{ML} = \argmax_{c} p(y|c) = \argmax_{c=c_1, c_2, \cdots, c_n}  \prod_{i=1}^{n}p(y_i|c_i), \label{eq:MLDecoder}
\end{equation}
where the maximum is over all valid codewords, i.e. all paths through the trellis.

On the trellis, each codeword is a path, and the ML decoder looks for the path that best explains the received sequence. Decoding works because different paths differ in many positions: two paths that split apart must differ in at least \(d_{free}\) coded bits before they merge again. This is exactly the free distance property of the previous lecture.

The difficulty is the number of candidates. A message of \(L\) bits has \(2^L\) possible codewords, so evaluating Eq.~\ref{eq:MLDecoder} by brute force is hopeless even for \(L = 100\). The Viterbi algorithm solves this problem with effort that grows only linearly in \(L\).

\section{A Hard Decision Decoder}\label{sec:hard}
The simplest case is the binary symmetric channel with crossover probability \(p < \frac{1}{2}\). The same situation arises on the AWGN channel if the receiver first makes a \emph{hard decision} on each received value, deciding bit \(0\) if \(y > 0\) and bit \(1\) otherwise (using the mapping \(0 \mapsto +1\), \(1 \mapsto -1\)), and passes only these bits to the decoder.

On the BSC, each received bit either agrees with the transmitted bit (probability \(1-p\)) or disagrees (probability \(p\)). If the received sequence \(y\) differs from a candidate codeword \(c\) in \(d_H(y,c)\) positions, out of \(N = nr\) coded bits in total, then
\[p(y|c) = p^{d_H(y,c)} (1-p)^{N - d_H(y,c)} = (1-p)^N \left(\frac{p}{1-p}\right)^{d_H(y,c)}.\]
Since \(p < \frac{1}{2}\), the ratio \(p/(1-p)\) is less than \(1\), so \(p(y|c)\) decreases as \(d_H(y,c)\) increases. Therefore
\begin{equation}
c_{ML} = \argmin_{c} d_H(y,c) = \argmin_{c} \sum_{i=1}^{n} d_H(y_i, c_i). \label{eq:HardML}
\end{equation}
On the BSC, the ML decoder is the \emph{minimum Hamming distance} decoder: it picks the codeword closest to the received bits, and the value of \(p\) does not even need to be known. The distance splits into a sum of per-block distances \(d_H(y_i, c_i)\), each between \(0\) and \(r\), and this additive structure is what the Viterbi algorithm exploits.

Hard decisions are simple, but they throw information away. A received value \(y = 0.05\) and a received value \(y = 2.3\) are both turned into bit \(0\), even though the first is far less reliable. On the AWGN channel, this costs about \(2\) dB of signal-to-noise ratio compared with soft-decision decoding, which we develop next.

\section{A Soft Decision Decoder}\label{sec:soft}
\subsection{Log-likelihood}
A soft-decision decoder works directly with the channel outputs \(y_i\), without first rounding them to bits. Since the logarithm is monotonically increasing, Eq.~\ref{eq:MLDecoder} is equivalent to
\begin{align}
    c_{ML} &= \argmax_{c} \log p(y|c) \nonumber \\
           &= \argmax_{c=c_1, c_2, \cdots, c_n} \log \prod_{i=1}^{n}p(y_i|c_i) \nonumber \\
           &= \argmax_{c=c_1, c_2, \cdots, c_n} \sum_{i=1}^{n} \log p(y_i|c_i). \label{eq:ML_Viterbi}
\end{align}
Taking the logarithm turns the product into a sum, which is what makes the dynamic program of Section~\ref{sec:dp} possible.

\subsection{Normalization and Log-likelihood Ratio}
Subtracting a quantity that does not depend on the candidate codeword from each term of Eq.~\ref{eq:ML_Viterbi} does not change the argmax. A convenient choice is to subtract \(\log p(y_i|\mathbf{1})\), the log-likelihood of receiving \(y_i\) if the all-one block \(\mathbf{1} = 11\cdots1\) had been sent. (Any fixed reference block would do; the all-one block makes the formulas simplest.) This gives
\begin{align}
    c_{ML} &= \argmax_{c=c_1, c_2, \cdots, c_n} \sum_{i=1}^{n} \big(\log p(y_i|c_i) - \log p(y_i|\mathbf{1})\big) \nonumber \\
    &=\argmax_{c=c_1, c_2, \cdots, c_n} \sum_{i=1}^{n} \log \frac{p(y_i|c_i)}{p(y_i|\mathbf{1})}. \label{eq:CovnCML}
\end{align}

The quantity \(\log \frac{p(y_i|c_i)}{p(y_i|\mathbf{1})}\) is the log-likelihood ratio between the candidate block \(c_i\) and the all-one block. Normalizing removes constant factors from \(p(y_i|c_i)\), such as the \(\frac{1}{2\pi\sigma^2}\) in the Gaussian density, and it keeps the numbers in a small range, which matters in practical software and hardware implementations.

\begin{example}
On the binary symmetric channel, suppose the transmitted block is \(c_i = 01\) and the received block is \(y_i = 11\). The first bit was flipped and the second was not, so
\[p(y_i|c_i) = p(1-p), \qquad \log p(y_i|c_i) = \log\big(p(1-p)\big),\]
and the normalized log-likelihood ratio is
\begin{align*}
\log \frac{p(y_i|c_i)}{p(y_i|11)} = \log \frac{p(1-p)}{(1-p)(1-p)} = \log \frac{p}{1-p}.
\end{align*}
This is negative for \(p < \frac{1}{2}\): the candidate \(01\) explains the received \(11\) less well than \(11\) does.
\end{example}

\begin{example}
On the AWGN channel with noise \(N(0, \sigma^2)\), we map bit \(0\) to \(+1\) and bit \(1\) to \(-1\). Suppose the transmitted block is \(c_i = 01\), i.e. the signal \((+1, -1)\), and the received block is \(y_i = (y_0, y_1)\). Then
\[p(y_i|c_i) = \frac{1}{2\pi\sigma^2} \exp\left[-\frac{(y_0-1)^2+(y_1 + 1)^2}{2\sigma^2}\right],\]
the log-likelihood is
\[\log p(y_i|c_i) = \log\frac{1}{2\pi\sigma^2} -\frac{(y_0-1)^2+(y_1 + 1)^2}{2\sigma^2},\]
and the normalized log-likelihood ratio is
\begin{align*}
\log \frac{p(y_i|c_i)}{p(y_i|11)} &= -\frac{(y_0-1)^2+(y_1 + 1)^2}{2\sigma^2} + \frac{(y_0+1)^2+(y_1 + 1)^2}{2\sigma^2} \\
&= \frac{2y_0}{\sigma^2}.
\end{align*}
This last expression is surprisingly simple, and it makes intuitive sense. The candidate \(01\) and the reference \(11\) differ only in the first bit, so only \(y_0\) matters. A positive \(y_0\) is evidence that the first bit is \(0\), which favors \(01\); a negative \(y_0\) favors \(11\). The larger \(|y_0|\), the stronger the evidence. The quantity \(\frac{2y_0}{\sigma^2} = \log \frac{p(y_0|0)}{p(y_0|1)}\) is the log-likelihood ratio of the first bit.
\end{example}

\section{Branch Metric}\label{sec:branch}
We define the \(i\)th \emph{branch metric} to be the normalized log-likelihood ratio of the block \(c_i\):
\begin{equation}
  B_i(c_i) = \log \frac{p(y_i|c_i)}{p(y_i|\mathbf{1})}. \label{eq:BranchMetric}
\end{equation}
The maximum likelihood decision in Eq.~\ref{eq:CovnCML} then becomes
\begin{align}
    c_{ML} &=\argmax_{c=c_1, c_2, \cdots, c_n} \sum_{i=1}^{n} B_i(c_i). \label{eq:ConvBranchML}
\end{align}

The two examples above follow a general pattern. Because the channel is memoryless, the branch metric splits over the bits of the block. Bits where \(c_i^j = 1\) agree with the reference and contribute nothing, so
\begin{equation}
B_i(c_i) = \sum_{j:\, c_i^j = 0} L(y_i^j), \qquad \text{where } L(y) = \log\frac{p(y|0)}{p(y|1)} \label{eq:BranchLLR}
\end{equation}
is the log-likelihood ratio (LLR) of a single received value. For the two channels in this lecture:
\begin{itemize}
    \item on the BSC, \(L(y) = +\log\frac{1-p}{p}\) if \(y = 0\) and \(L(y) = -\log\frac{1-p}{p}\) if \(y = 1\);
    \item on the AWGN channel, \(L(y) = \frac{2y}{\sigma^2}\).
\end{itemize}
Only the LLRs of the received values are needed, and for each time step there are only \(2^r\) distinct branch metrics, one per possible block \(c_i\), which are computed once and shared by all branches with the same label. For the BSC, maximizing \(\sum_i B_i\) is equivalent to minimizing the Hamming distance, as in Eq.~\ref{eq:HardML}, and in practice hard-decision decoders simply use \(d_H(y_i, c_i)\) as the branch metric and minimize.

We now label each branch of the trellis with its branch metric. The trellis becomes a weighted graph, with a weight on every branch from a state at time \(i-1\) to a state at time \(i\). The ML decoding problem becomes: \emph{find the path through the trellis with the largest total weight.} Seen in this light, the problem has a well-known solution: dynamic programming.

\section{Dynamic Programming}\label{sec:dp}
We label the trellis states \(0, 1, \ldots, 2^{K-1}-1\), where \(K\) is the constraint length. In our example, \(K=3\), and the states \(00, 01, 10, 11\) are labeled \(0, 1, 2, 3\).

The encoder starts in state \(0\) at time \(0\). A codeword of \(n\) blocks is a path of \(n\) branches from state \(0\) at time \(0\) to some state at time \(n\), and the ML codeword is the path with the largest sum of branch metrics:
\begin{align}
    B_{ML} &=\max_{c=c_1, c_2, \cdots, c_n} \sum_{i=1}^{n} B_i(c_i). \label{eq:BML}
\end{align}
If the message is terminated with \(K-1\) zeros, as described in the previous lecture, then every codeword ends in state \(0\), and only paths ending there need to be considered.

The key observation is that the best path to a state at time \(j\) can be built from the best paths to states at time \(j-1\). Formally, for each state \(s\) and time \(j\), define the \emph{path metric} (cumulative branch metric) as the largest total metric of a partial path from state \(0\) at time \(0\) to state \(s\) at time \(j\):
\begin{equation*}
    CB_{j}(s) = \max_{\substack{c_1, c_2, \cdots, c_j \\ \text{ending in state } s}} \sum_{i=1}^{j} B_i(c_i),
\end{equation*}
with \(CB_0(0) = 0\) and \(CB_0(s) = -\infty\) for \(s \neq 0\). Then \(B_{ML} = \max_s CB_{n}(s)\), or \(B_{ML} = CB_n(0)\) for a terminated code.

\begin{theorem}[Principle of optimality]\label{thm:dp}
For a state \(s\), let \(P(s)\) be the set of states that can transition to \(s\) in one step, and for \(s' \in P(s)\) let \(c(s',s)\) be the coded block produced on the branch from \(s'\) to \(s\). Then
\begin{equation}
    CB_j(s) = \max_{s' \in P(s)} \Big(CB_{j-1}(s') + B_j\big(c(s',s)\big)\Big). \label{eq:ACS}
\end{equation}
\end{theorem}
\begin{proof}
Every partial path that ends in state \(s\) at time \(j\) passes through some predecessor \(s' \in P(s)\) at time \(j-1\) and then takes the branch from \(s'\) to \(s\). Its metric is the metric of its first \(j-1\) branches plus \(B_j(c(s',s))\). For a fixed \(s'\), this is largest when the first \(j-1\) branches form the best partial path to \(s'\), whose metric is \(CB_{j-1}(s')\). If they did not, we could replace them with that best partial path and increase the total. Maximizing over the choice of \(s'\) gives Eq.~\ref{eq:ACS}.
\end{proof}

For a rate-\(1/r\) code, every state has exactly two predecessors, corresponding to the two possible values of the bit that just left the shift register. So Eq.~\ref{eq:ACS} is a single \emph{add--compare--select} (ACS) operation: add the branch metric to each of the two incoming path metrics, compare the two sums, and select the larger. The predecessor that wins is recorded as the state's \emph{survivor}; the losing path can never be part of the ML path and is discarded. At every time step, each state keeps exactly one surviving path, so the decoder tracks only \(2^{K-1}\) paths instead of the \(2^j\) paths through the trellis.

\section{Put it together - the Viterbi Algorithm}\label{sec:viterbi}
The Viterbi algorithm consists of three steps:
\begin{enumerate}
    \item \textbf{Branch metrics.} At each time step \(j\), compute the \(2^r\) branch metrics \(B_j(c)\) for all possible blocks \(c\) from the received values \(y_j\), using Eq.~\ref{eq:BranchLLR} (or the Hamming distance \(d_H(y_j, c)\) for hard decisions).
    \item \textbf{Forward pass.} Starting from \(CB_0(0) = 0\), \(CB_0(s) = -\infty\) for \(s \neq 0\), apply the ACS recursion Eq.~\ref{eq:ACS} for \(j = 1, 2, \ldots, n\), and store the survivor of every state at every time.
    \item \textbf{Traceback.} Start from the final state (state \(0\) for a terminated code, otherwise the state with the best path metric) and follow the survivors backwards to time \(0\). The branches along this path give the ML codeword, and their input bits give the decoded message.
\end{enumerate}
For hard decisions it is customary to use Hamming distances and replace every max by a min; by Eq.~\ref{eq:HardML} this gives the same decisions.

\begin{example}\label{ex:viterbi}
We encode the message \(x = 1011\) with our example \((7,5)\) code, followed by two tail zeros to return the encoder to state \(00\). Following the branch table in the Introduction, the encoder visits the states
\[00 \to 10 \to 01 \to 10 \to 11 \to 01 \to 00\]
and produces the codeword
\[c = 11\ \ 10\ \ 00\ \ 01\ \ 01\ \ 11.\]
The BSC flips two bits, the second bit of block \(2\) and the first bit of block \(5\), so the decoder receives
\[y = 11\ \ 11\ \ 00\ \ 01\ \ 11\ \ 11.\]

We run the hard-decision Viterbi algorithm, using the Hamming distance as the branch metric and keeping the smaller metric at each state. The table lists the path metric of each state after each time step, with its survivor (predecessor state) in parentheses; a dash means the state cannot be reached. During the last \(K - 1 = 2\) steps, only input \(0\) is allowed because these are tail bits.
\begin{center}
\begin{tabular}{c|cccccc}
\hline
time \(j\) & 1 & 2 & 3 & 4 & 5 & 6 \\
received \(y_j\) & 11 & 11 & 00 & 01 & 11 & 11 \\
\hline
state 00 & 2 (00) & 4 (00) & 3 (01) & 3 (01) & 2 (01) & \textbf{2} (01) \\
state 01 & -- & 1 (10) & 2 (11) & 2 (11) & 2 (11) & -- \\
state 10 & 0 (00) & 2 (00) & 1 (01) & 3 (01) & -- & -- \\
state 11 & -- & 1 (10) & 2 (11) & 1 (10) & -- & -- \\
\hline
\end{tabular}
\end{center}

Let us check a few entries. At \(j=1\), from state \(00\) the branch with input \(0\) outputs \(00\), at distance \(2\) from \(y_1 = 11\), and the branch with input \(1\) outputs \(11\), at distance \(0\); so \(CB_1(00) = 2\) and \(CB_1(10) = 0\). At \(j = 3\), state \(10\) can be reached from \(00\) (output \(11\), distance \(2\) from \(y_3 = 00\), total \(4 + 2 = 6\)) or from \(01\) (output \(00\), distance \(0\), total \(1 + 0 = 1\)); the decoder keeps the path from \(01\) with metric \(1\). At \(j=4\), state \(00\) can be reached from \(00\) (total \(3 + 1 = 4\)) or from \(01\) (total \(2 + 1 = 3\)), so the survivor is \(01\).

The final path metric is \(CB_6(00) = 2\): the best codeword is at Hamming distance \(2\) from the received sequence, matching the two channel errors. Tracing back the survivors from state \(00\) at \(j = 6\),
\[00 \xleftarrow{} 01 \xleftarrow{} 11 \xleftarrow{} 10 \xleftarrow{} 01 \xleftarrow{} 10 \xleftarrow{} 00,\]
which is exactly the encoder's state sequence. The first bit of each new state is the input bit that produced it, so the decoded input is \(1\,0\,1\,1\,0\,0\), and after removing the two tail bits we recover the message \(1011\). Both errors are corrected.

The two errors are three blocks apart. Since \(d_{free} = 5\), any two errors are corrected, but three errors close together may not be. When errors are well separated, however, the Viterbi decoder can correct many more than two errors in a long sequence, because each error event involves only a short stretch of the trellis.
\end{example}

\paragraph{Practical details.}
\begin{itemize}
    \item \emph{Metric normalization.} Path metrics grow without bound. Since only differences between path metrics matter, implementations periodically subtract the smallest (or largest) path metric from all of them to keep the numbers in a fixed range.
    \item \emph{Ties.} If the two candidates in an ACS step have equal metrics, either choice is ML; implementations pick one by a fixed rule.
    \item \emph{Truncated traceback.} For long or continuous streams, waiting for the end of the message before tracing back requires too much memory and delay. In practice, the survivors of all states almost always agree on the decisions made more than about \(5K\) steps in the past. A decoder can therefore trace back a fixed depth \(D \approx 5K\) from the current best state and release the oldest bit, with negligible loss in performance.
\end{itemize}

\section{Varying the code rate}\label{sec:rate}
A rate-\(1/r\) convolutional code with \(r\) generators produces \(r\) coded bits per information bit. Termination adds \(K-1\) tail bits, so a message of \(L\) bits is sent with \(r(L + K - 1)\) coded bits, and the actual rate is
\[R = \frac{L}{r(L+K-1)},\]
slightly less than \(1/r\). This is the minor correction to the rate mentioned in the previous lecture. For \(L = 1000\) and \(K = 7\), the loss is under \(1\%\). For short messages, the loss can be avoided with \emph{tail-biting}, in which the encoder starts in the state given by the last \(K-1\) message bits, so the path starts and ends in the same state without any tail bits.

\paragraph{Lower rates.} Adding more generators lowers the rate. For example, a rate-\(1/3\) code uses three generators; the LTE cellular standard uses a rate-\(1/3\), \(K = 7\) tail-biting code for its control channels.

\paragraph{Higher rates: puncturing.} To obtain a rate higher than \(1/2\), we start from a rate-\(1/2\) \emph{mother code} and delete some of the coded bits according to a periodic pattern, called a \emph{puncturing matrix}. For example, the pattern
\[P = \begin{bmatrix} 1 & 1 \\ 1 & 0 \end{bmatrix}\]
means: over each period of two input bits, send \(p_0\) at both times but \(p_1\) only at the first time (a \(0\) marks a deleted bit). Two information bits now produce three coded bits, so the rate is \(2/3\). Similarly, the pattern \(\begin{bmatrix} 1 & 1 & 0 \\ 1 & 0 & 1 \end{bmatrix}\) sends four coded bits for every three information bits, giving rate \(3/4\).

Puncturing has two big practical advantages:
\begin{itemize}
    \item \emph{The same encoder and decoder serve all rates.} The encoder is unchanged; the transmitter just skips the punctured bits. The decoder uses the trellis of the mother code and treats each punctured position as an \emph{erasure}: its LLR is set to \(L = 0\) (or, for hard decisions, it is left out of the Hamming distance), so it favors neither \(0\) nor \(1\). Nothing else in the Viterbi algorithm changes.
    \item \emph{The rate can adapt to the channel.} By choosing nested puncturing patterns, a family of rate-compatible punctured convolutional (RCPC) codes is obtained from a single mother code. A system can then switch to a higher rate when the channel is good and a lower rate when it is poor. Wi-Fi (IEEE 802.11a/g), for example, obtains rates \(1/2\), \(2/3\), and \(3/4\) by puncturing the \(K=7\), \((133,171)\) code.
\end{itemize}
The price is a smaller free distance, since fewer coded bits separate competing paths:
\begin{center}
\begin{tabular}{lccc}
\hline
mother code & rate \(1/2\) & rate \(2/3\) & rate \(3/4\) \\
\hline
\(K=3\), \((7,5)\) & \(d_{free} = 5\) & \(d_{free} = 3\) & \(d_{free} = 3\) \\
\(K=7\), \((133,171)\) & \(d_{free} = 10\) & \(d_{free} = 6\) & \(d_{free} = 5\) \\
\hline
\end{tabular}
\end{center}

\section{The complexity of Viterbi Decoding}\label{sec:complexity}
Consider a rate-\(1/r\) code with constraint length \(K\), and a message of \(L\) bits.
\begin{itemize}
    \item \textbf{Computation.} Each time step has \(2^{K-1}\) states, each with two incoming branches, so the forward pass performs \(2^{K-1}\) ACS operations, i.e. \(2^K\) additions and \(2^{K-1}\) comparisons, per information bit. The \(2^r\) branch metrics per step add a small extra cost. The total work is proportional to \(L \cdot 2^K\): \emph{linear} in the message length, but \emph{exponential} in the constraint length.
    \item \textbf{Memory.} The decoder stores \(2^{K-1}\) path metrics and, for the traceback, one survivor bit per state per time step: \(2^{K-1} L\) bits for a full traceback, or \(2^{K-1} D\) bits with a truncated traceback of depth \(D \approx 5K\).
    \item \textbf{Latency.} With truncated traceback, each decoded bit is released about \(D\) steps after it was received.
\end{itemize}
Compared with brute-force ML decoding, which would compare \(2^L\) codewords, the savings are enormous. For the \(K=7\) code, the decoder performs \(64\) ACS operations per bit, which is easily done in hardware at gigabit rates. The exponential growth in \(K\) is the real limitation: each extra unit of constraint length doubles the work. Practical Viterbi decoders therefore use \(K \leq 9\), which in turn limits how close convolutional codes can come to the Shannon limit, as we see next.


\section{The performance of Convolution Codes}\label{sec:conv_perf}
How well do convolutional codes perform on a real channel, and how close do they come to the Shannon limit? In this section we answer this for the binary symmetric channel with crossover probability \(p\). On the BSC, the log-likelihood in Eq.~\ref{eq:ML_Viterbi} is a decreasing function of the Hamming distance between the received bits and the codeword, so the Viterbi decoder with Hamming-distance branch metrics is exactly the maximum likelihood (hard-decision) decoder. We study three standard rate-\(1/2\) codes of increasing constraint length:
\begin{center}
\begin{tabular}{cccccc}
\hline
\(K\) & generators (octal) & states & \(d_{free}\) & \(B_{d_{free}}\) & low-\(p\) approximation of \(P_b\) \\
\hline
3 & (7, 5) & 4 & 5 & 1 & \(50\,p^3\) \\
5 & (23, 35) & 16 & 7 & 4 & \(560\,p^4\) \\
7 & (133, 171) & 64 & 10 & 36 & \(4536\,p^5\) \\
\hline
\end{tabular}
\end{center}
The \(K=3\) code is our running example, \(g_0 = 1 + D + D^2\) and \(g_1 = 1 + D^2\). The \(K=7\) code is the industry-standard code used in deep-space missions, satellite links, and Wi-Fi. \(B_d\) and the approximation in the last column are explained below.

\subsection{Error events and the union bound}
Because the code is linear, we may assume the all-zero codeword is transmitted. A decoding error occurs when the Viterbi decoder chooses a path that leaves the all-zero state and later returns to it. Such a detour is called an \emph{error event}. If the detour has output weight \(d\), then the decoder prefers it to the correct path exactly when more than half of those \(d\) positions are flipped by the channel (with a coin flip on a tie when \(d\) is even). The probability of this is
\begin{equation}
P_d = \sum_{j=\lfloor d/2 \rfloor + 1}^{d} \binom{d}{j} p^j (1-p)^{d-j} \;+\; \frac{1}{2}\binom{d}{d/2} p^{d/2}(1-p)^{d/2}, \label{eq:Pd}
\end{equation}
where the last (tie) term is present only when \(d\) is even.
Now let \(B_d\) be the total number of information-bit errors, summed over all detours of output weight \(d\). These numbers come from the transfer function of the code, i.e. a weighted count of the paths through the state diagram. Adding up over all error events (the union bound) gives the standard estimate of the bit error rate:
\begin{equation}
P_b \leq \sum_{d = d_{free}}^{\infty} B_d\, P_d. \label{eq:ConvUnionBound}
\end{equation}
For the \((7,5)\) code, \(B_5, B_6, B_7, \ldots = 1, 4, 12, 32, 80, \ldots\), i.e. \(B_d = (d-4)\,2^{d-5}\).

For small \(p\), the smallest distances dominate. For the \((7,5)\) code, \(P_5 \approx \binom{5}{3}p^3 = 10p^3\), but \(P_6\) is also of order \(p^3\) because of the tie term: \(P_6 \approx \frac{1}{2}\binom{6}{3}p^3 = 10p^3\). So \(P_b \approx 1 \cdot 10p^3 + 4 \cdot 10p^3 = 50\,p^3\). In general,
\[P_b \propto p^{\lceil d_{free}/2 \rceil} \quad \text{as } p \to 0,\]
so the free distance sets the slope of the error curve. Doubling \(d_{free}\) roughly doubles the exponent: a code with \(d_{free} = 10\) has \(P_b \propto p^5\), while uncoded transmission has \(P_b = p\).

\subsection{Simulated performance}
Figure~\ref{fig:conv_bsc_ber} shows the bit error rate of hard-decision Viterbi decoding for the three codes, obtained by Monte Carlo simulation, together with the union bound Eq.~\ref{eq:ConvUnionBound} and uncoded transmission. Several lessons can be read off the figure.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.75\textwidth]{Figs/conv_bsc_ber.pdf}
    \caption{Bit error rate of rate-\(1/2\) convolutional codes on the BSC with hard-decision Viterbi decoding. Markers: simulation (frames of 1000 information bits, terminated to the zero state, at least 100 bit errors per point). Dashed: union bound Eq.~\ref{eq:ConvUnionBound}. The vertical line marks the largest crossover probability at which rate-\(1/2\) communication is possible, \(1 - H(p) = 1/2\).}
    \label{fig:conv_bsc_ber}
\end{figure}

\begin{itemize}
    \item \textbf{Coding helps a lot at moderate noise.} At \(p = 0.01\), uncoded transmission has \(P_b = 10^{-2}\), while even the 4-state \((7,5)\) code achieves \(P_b \approx 5 \times 10^{-5}\).
    \item \textbf{Larger \(K\) buys a steeper curve.} The slopes \(p^3, p^4, p^5\) predicted by \(d_{free}\) are clearly visible. To reach \(P_b = 10^{-5}\), the three codes tolerate \(p \approx 0.006\), \(0.012\), and \(0.018\) respectively. The price is complexity: the number of trellis states, and hence the Viterbi decoding effort, grows as \(2^{K-1}\), i.e. \(4, 16, 64\).
    \item \textbf{The union bound is tight at low noise and useless at high noise.} Below \(P_b \approx 10^{-3}\), the bound and the simulation agree closely, so Eq.~\ref{eq:ConvUnionBound} is the standard design tool. For larger \(p\), the bound diverges, because it counts overlapping error events many times.
    \item \textbf{At high noise, stronger codes are worse.} For \(p \gtrsim 0.08\), the ordering reverses, and near \(p = 0.1\) the coded bit error rate even exceeds the uncoded one. When errors are dense, the decoder follows long wrong paths, and a code with a longer memory spreads each wrong decision over more bits.
\end{itemize}

\subsection{The gap to the Shannon limit}
By the channel coding theorem, a rate-\(1/2\) code can communicate reliably on the BSC whenever \(1 - H(p) > 1/2\), i.e. for all \(p < 0.110\). The best code in the figure needs \(p \approx 0.018\) for \(P_b = 10^{-5}\). The capacity of that channel is \(1 - H(0.018) \approx 0.87\), so the \(K=7\) code uses only about \(57\%\) of the available capacity. Equivalently, Shannon's theorem promises reliable communication at a noise level about six times higher than the best convolutional code can handle.

On the AWGN channel the same comparison is usually stated in terms of SNR. With soft-decision Viterbi decoding, the \(K=7\) code reaches \(P_b = 10^{-5}\) at \(E_b/N_0 \approx 4.4\) dB, compared with about \(0.2\) dB for the Shannon limit of a rate-\(1/2\) binary-input code. This is a gap of roughly \(4\) dB. Hard decisions, i.e. first converting the channel into a BSC as in this section, cost about another \(2\) dB. Increasing \(K\) narrows the gap only slowly, since the decoding complexity grows exponentially in \(K\). Closing this gap required a new idea: the turbo codes and LDPC codes of the following lectures, which operate within a fraction of a dB of the Shannon limit.
